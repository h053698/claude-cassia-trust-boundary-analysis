# 탐지 시그널

이 취약점 클래스를 노리는 자동화/남용을 식별하기 위한 서버측 신호.

## 불일치 기반

- **통로 불일치율**: 서버가 내려준 `checkout_flow`와 실제 제출된 값이 다른 비율. 특정 IP/디바이스 지문/계정군에서 급증하면 의심.
- **정책-제출 미스매치 재발**: 동일 org에서 "정책=카드인데 제출=은행출금"이 반복.

## 라이프사이클 기반

- **개통→반송→취소 사이클**: "즉시 개통 → T+1~3 뒤 청산 실패(R-코드) → 취소" 패턴이 특정 계정군에서 높은 비율.
- **R-코드 클러스터**: R02(무효 계좌) 등 특정 반송 코드가 짧은 기간 특정 세그먼트에 몰림.

## 행동 기반

- **초고속 제출**: capabilities 조회 → 제출 간격이 비정상적으로 짧고 균일(자동화 흔적).
- **세션 실패 패턴**: "세션 검증 통과 → 결제 페이지 → 제출 시 세션 실패"가 반복되는 org.
- **단일 계좌 문자열 재사용**: 서로 다른 계정이 동일한 형식-유효 계좌 문자열을 제출.

## 감시할 "신호 엔드포인트"

결제 로직에 영향을 주면서 클라이언트가 응답을 관측/조작할 수 있는 것들:

- `checkout_capabilities`, `payment_methods`, `available_plans`
- `eligible_promotions`, `offers`, `discounts`
- `feature_flags`, `entitlements`, `subscription_tiers`
- `region`, `locale`, `country_detection`

이런 엔드포인트는 "응답을 신뢰하는가"를 항상 의심하고, 후속 제출에서 재검증하는지 감사한다.
