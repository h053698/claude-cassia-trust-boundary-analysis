# 로컬 무해 데모

이 데모는 **개념 재현용**이다. 실제 결제망·실서비스와 통신하지 않는다. 모든 서버는 `localhost`에서 돌아가는 가짜 결제 백엔드이며, "결제 성공"은 콘솔 로그일 뿐 실제 돈이 오가지 않는다.

목적: **"서버가 클라이언트의 결제 통로 선택을 신뢰하면 왜 위험한가"**와 **"어떻게 고치면 막히는가"**를 나란히 보여준다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `vulnerable-server.js` | 취약 구현. 클라이언트가 보낸 `checkout_flow`를 신뢰하고, 비동기 결제를 즉시 개통한다. (port 3000) |
| `fixed-server.js` | 수정 구현. 서버가 통로를 자체 결정·재검증하고, 비동기 결제는 청산 확인까지 개통을 지연한다. (port 3001) |
| `attack-client.js` | 조작된 `checkout_flow=cassia` + 형식만 유효한 (가짜) 로컬 계좌번호를 제출하는 클라이언트. |
| `iban-format-check.js` | MOD 97-10 **형식 검증기**. 형식이 "실재성"을 뜻하지 않음을 보여주는 교육용. 계좌 생성기가 아니다. |

## 실행

```bash
# 1) 취약 서버 시연
node vulnerable-server.js         # 터미널 A
node attack-client.js             # 터미널 B → "개통됨" (취약)

# 2) 수정 서버 시연
node fixed-server.js              # 터미널 A
node attack-client.js --port 3001 # 터미널 B → "거부됨" (안전)
```

요구사항: Node.js 18+ (내장 `http`만 사용, 의존성 없음).

## 왜 진짜 우회 코드가 없나

실제 claude.ai 결제를 우회하는 코드나, 실결제망에 밀어넣을 수 있는 유효 IBAN 대량 생성기는 사기 도구가 된다. 이 데모는 **동일한 취약점 원리**를 로컬 목업으로만 재현해, 방어를 검증할 수 있게 한다. 원리 이해와 방어 검증에는 이걸로 충분하다.
